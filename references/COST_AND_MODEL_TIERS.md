# Cost Optimization & Asymmetric Model Tiering (非对称模型分工与 Token 成本极致优化指南)

本指南深入分析为什么 **双端 Agent 架构不仅能保证工程质量，而且在经济账（Token 成本与订阅花销）上具有颠覆性优势**。

---

## 1. 核心经济原理：非对称算力分配 (Asymmetric Compute)

软件开发中不同工种所消耗的 Context 长度与推理深度有着本质区别：

| 任务类型 | 所需能力特质 | 传统纯 API 全用旗舰模型 (如 o1 / Opus) | 双端分工模式 (网页端旗舰 + 本地轻量端) | 成本降幅 |
| :--- | :--- | :--- | :--- | :--- |
| **项目规划与架构**<br>(Phase 0: 需求分解、技术选型) | **极高智商、深度推理、长线思考**。<br>单次产出少（数千字），但思考要求极高。 | API 计费极其昂贵（按 Reasoning Token 叠加收费）。 | **ChatGPT 网页端包月会员 ($20/月)**。<br>利用 o1 / o3-mini / GPT-4o 深度思考，**按月固定成本，无按 Token 计费**。 | **趋近于 0 额外成本** |
| **日常实施与补全**<br>(Phase 1-3: 敲样板代码、写单测) | **执行力强、工具调用熟练、速度快**。<br>上下文吞吐极大（代码库反复读写、跑测试输出大量日志）。 | API Token 消耗天文数字，上下文很容易打满爆费。 | **本地低成本模型 / 免费配额端 (Codex / Flash / Haiku / 本地模型)**。<br>仅需严格依照 Lead 指令做最小实现。 | **降低 80% ~ 95%** |
| **验收审查与裁决**<br>(Phase 3-4: 视觉审查、门禁判定) | **多模态 Vision 审查、决策定力**。 | API 上传多张高分辨率图片，Vision API Token 昂贵。 | **网页端原生多模态窗口**。<br>直接粘贴截图进行视觉像素级审查，零额外 API 账单。 | **固定在网页会员内** |

## 2. 经典落地组合推荐 (Recommended Pairings)

### 组合 A：极致性价比方案 (ChatGPT Plus/Team 网页端 + 本地轻量模型/Codex)
- **Project Lead**: 网页端 **o1-preview / o3-mini / GPT-4o** (每月 $20 固定订阅，不计 Token)。
  - 负责：深度架构设计、需求契约、Review 截图与代码 Diff。
- **Chief Engineer**: 本地 **OpenAI Codex / GPT-4o-mini / Claude 3.5 Haiku / Gemini Flash**。
  - 负责：调用终端工具、执行批处理测试、读写文件。因为每批次目标已被 Lead 极其精准地压缩收敛，低成本模型绝不会迷路，极速完成且花费极低。

### 组合 B：混合开源本地方案 (Claude Web + 本地开源 Qwen/DeepSeek)
- **Project Lead**: 网页端 **Claude 3.5 Sonnet / Opus**。
- **Chief Engineer**: 本地 Ollama 运行的 **DeepSeek-Coder-V2 / Qwen2.5-Coder**。
  - 本地编码与测试执行 **Token 费用彻底为 0**，完全自闭环。

## 3. 为什么低级模型在双端模式下“不会写烂代码”？

很多人不敢用轻量模型写代码，是因为让轻量模型直接做全局大项目时，它会：
1. 理解错宏观需求；
2. 擅自改动无关代码引发大面积报错；
3. 遇到报错胡乱打补丁越修越烂。

而在 **`dual-agent-loop`** 体系下，轻量模型被彻底锁紧在三道硬约束中：
1. **指令收敛 (Directive Locking)**：高级模型已经把宏观需求拆解为**仅需修改 1~2 个纯函数或补齐一个类的最小指令**，轻量模型无需理解全局复杂度。
2. **零回归门禁 (A/B Regression Gate)**：本地脚本自动比对 `HEAD-ONLY = 0`，只要轻量模型敢写出副作用，测试门禁立即熔断，逼它在本地最小范围内自愈。
3. **高级模型外审 (Lead Acceptance)**：每次提交必须向网页端高级模型交付完工证据包，高级模型亲自把关代码 Diff，通不过直接下发 REWORK。

**结论**：高低模型搭配不但成本节省 90% 以上，工程确定性反而远超单一大模型。
